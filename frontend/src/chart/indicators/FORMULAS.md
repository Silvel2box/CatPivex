# Indicator formulas (locked)

Semantics follow Pine Script v5 built-ins (what TradingView charts show) and TA-Lib, which agree
for everything below. Input is `Candle[]` ascending; `close` unless stated. Index `i` is 0-based.
A line has **no point** at bars where it is undefined (never NaN/undefined in output).

| Type   | Params (default)           | Lines                    | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------ | -------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sma`  | period 20                  | `value`                  | mean of the last `period` closes. First point at `i = period-1`.                                                                                                                                                                                                                                                                                                                                                                                 |
| `ema`  | period 12                  | `value`                  | `α = 2/(period+1)`. Seed at `i = period-1` = SMA of the first `period` closes; then `ema = α·close + (1-α)·ema[i-1]`. (Pine `ta.ema`, TA-Lib `EMA`.)                                                                                                                                                                                                                                                                                             |
| `bb`   | period 20, mult 2          | `upper` `middle` `lower` | `middle` = SMA(period); `σ` = **population** std-dev (divide by `period`) of the same closes; `upper/lower = middle ± mult·σ`. (Pine `ta.bb`, TA-Lib `BBANDS`.)                                                                                                                                                                                                                                                                                  |
| `rsi`  | period 14                  | `value`                  | Wilder. `change = close[i]-close[i-1]`, `gain = max(change,0)`, `loss = max(-change,0)`. Seed at `i = period`: `avgGain/avgLoss` = simple mean of the first `period` gains/losses (bars 1..period). Then `avg = (avg·(period-1) + x)/period`. `rsi = 100 - 100/(1+avgGain/avgLoss)`; edge cases in the note below. (Pine `ta.rsi`, TA-Lib `RSI`.)                                                                                                |
| `macd` | fast 12, slow 26, signal 9 | `macd` `signal` `hist`   | `macd = EMA(close,fast) - EMA(close,slow)` using the EMA above (each seeded with its own SMA; first point at `i = max(fast,slow)-1`). `signal` = EMA(signal) of the `macd` series, seeded with the SMA of its first `signal` values (first point at `i = max(fast,slow)+signal-2`). `hist = macd - signal`. Build fixtures from TA-Lib `EMA()` calls (TA-Lib `MACD()` aligns the fast EMA start to the slow one, which can seed it differently). |
| `vwap` | —                          | `value`                  | Typical price `tp = (high+low+close)/3`. Cumulative `Σ(tp·volume)/Σ(volume)` since the first bar of the current **session day**; resets when the day key changes. Day key from the symbol's exchange: `BINANCE`, `FX` → UTC date; `SET` → Asia/Bangkok date; `US` → America/New_York date. Zero cumulative volume → no point. Intraday intervals only (hidden on 1D/1W).                                                                         |

RSI edge note (Pine `ta.rsi`): `avgLoss = 0` → 100 (also when both are 0); else `avgGain = 0` → 0.
Fixtures avoid flat windows (libraries differ there); a unit test pins this choice.

Realtime: a bar with the same `time` as the last bar replaces it; a newer bar is appended.
Incremental results must equal a full recompute (T3.2).

## Phase 7 additions (locked)

`SMA(x, n)` below = mean of the last `n` defined values of series `x` (first point once `n` exist).

- **`stoch`** (kLength 14, kSmooth 3, dSmooth 3) → `k`, `d`. `raw = 100·(close − LL)/(HH − LL)` with `HH`/`LL` = highest high / lowest low of the last `kLength` bars (first at `i = kLength−1`); `HH = LL` → `raw = 0` (TA-Lib). `k = SMA(raw, kSmooth)`, `d = SMA(k, dSmooth)`. Fixture: TA-Lib `STOCHF(fastk=kLength, fastd=1)` for `raw`, then `talib.SMA` twice (TA-Lib `STOCH` starts `k` at `d`'s first bar).
- **`stochrsi`** (rsiLength 14, stochLength 14, kSmooth 3, dSmooth 3) → `k`, `d`. `r = rsi(close, rsiLength)` (the `rsi` above). `raw = 100·(r − min)/(max − min)` over the last `stochLength` values of `r`; `max = min` → `raw = 0`. `k = SMA(raw, kSmooth)`, `d = SMA(k, dSmooth)` (Pine's Stoch RSI). Fixture: `talib.RSI` + pandas rolling min/max/mean.
- **`atr`** (period 14) → `value`. `TR₀ = high − low`; `TRᵢ = max(high − low, |high − closeᵢ₋₁|, |low − closeᵢ₋₁|)`. TA-Lib seeding: first point at `i = period` = mean of `TR₁..TR_period` (bar 0 is not used), then `atr = (atr·(period−1) + TR)/period`. Pine seeds with bar 0 included one bar earlier; the two converge within the warm-up. Fixture: `talib.ATR`.
- **`supertrend`** (atrPeriod 10, factor 3) → `up`, `down` (gaps). Pine `ta.supertrend` with the `atr` above and `src = (high+low)/2`: `upper = src + factor·atr`, `lower = src − factor·atr`; `lower := lower > prevLower or close[1] < prevLower ? lower : prevLower`, `upper := upper < prevUpper or close[1] > prevUpper ? upper : prevUpper` (prev = 0 before the first defined bar); direction = `1` on the first defined bar, else `prevST == prevUpper ? (close > upper ? −1 : 1) : (close < lower ? 1 : −1)`; `st = direction == −1 ? lower : upper`. `up = st` when direction is −1 (uptrend), `down = st` when 1. Fixture: a numpy loop of this rule over `talib.ATR` in `gen_fixtures.py`.
- **`pivot`** (kind 0 Standard / 1 Fibonacci / 2 Camarilla, timeframe 0 Auto / 1 Day / 2 Week / 3 Month) → `P`, `R1..R4`, `S1..S4` (gaps). Needs `ctx.daily` (1D candles, time = 00:00 UTC of the trading date). Auto: interval ≤ 15m → Day, 30m–4h → Week, 1D/1W → Month. Period of a daily candle: its UTC date; week = ISO week (Monday start) of that date; month = `yyyy-mm`. Period of a chart bar: intraday → `ctx.dayKey(time)`; 1D/1W → UTC date; then week/month of that date. `H/L/C` = max high, min low, last close of the daily candles in the previous period (the latest period in `daily` before the bar's own). None → no point.
  - Standard: `P = (H+L+C)/3`, `R1 = 2P − L`, `S1 = 2P − H`, `R2 = P + (H−L)`, `S2 = P − (H−L)`, `R3 = H + 2(P − L)`, `S3 = L − 2(H − P)`.
  - Fibonacci: same `P`; `R1/S1 = P ± 0.382(H−L)`, `R2/S2 = P ± 0.618(H−L)`, `R3/S3 = P ± (H−L)`.
  - Camarilla: same `P`; `R1/S1 = C ± 1.1(H−L)/12`, `R2/S2 = C ± 1.1(H−L)/6`, `R3/S3 = C ± 1.1(H−L)/4`, `R4/S4 = C ± 1.1(H−L)/2`.
  - `R4`/`S4` only for Camarilla. Fixture: pandas groupby of daily candles + `shift(1)`.

`gaps: true` lines: the chart shows a break (whitespace) on bars where the line has no value, instead of joining across. Lightweight Charts 5.3 joins real points across whitespace, so the point before a gap is also drawn transparent (it colours the segment that starts there). The legend leaves out a gaps line that has no value at the shown bar.

## Phase 9: Volume Profile, visible range (`vrvp`, locked)

Not a per-bar series: the def has `rangeOverlay: true`, its `calc` emits nothing, and the profile is computed by `volumeProfile(bars, rows, valueAreaPct)` (`volumeProfile.ts`) over the bars on screen and drawn by `VolumeProfilePrimitive` on the candle pane (`zOrder` `bottom`: below grid and candles). Params: `rows` 24 (10–200), `valueArea` 70 (5–95, step 5), `width` 30 (10–60, step 5, % of the pane width). Colours (`kind: 'profile'`, colour only, no width): `up` `#2962ff`, `down` `#fbc02d`, `poc` `#f23645`. Legend label `VRVP rows va width`; its one value is the POC price (middle of the POC row) in the POC colour.

- **Bars**: indices `ceil(from) .. floor(to)` of the chart's visible logical range, clamped to `0 .. bars−1` (`visibleBarRange`); nothing visible → no profile.
- **Rows**: `min` = lowest low, `max` = highest high of those bars, `step = (max − min)/rows`; row `j` = `[min + j·step, min + (j+1)·step]`, the top row's high is exactly `max`.
- **Volume per row**: a bar with `high > low` adds `volume · overlap/(high − low)` to each row it overlaps (`overlap` = length of `[low, high] ∩ row`). A bar with `high == low` puts all its volume into row `min(rows−1, floor((price − min)/step))` (rows are half-open `[low, high)` except the top, which includes `max`); if every bar is flat at one price (`step = 0`) everything goes into the top row. `close ≥ open` → `up`, else `down`.
- **POC**: the row with the largest `up + down`; a tie → the lower row.
- **Value area**: start with the POC row; while its volume `< valueArea% · total`, add the adjacent row just above or just below the area, whichever has more volume (tie → above; one side exhausted → the other). Output `vaLow`/`vaHigh` = row indices.
- **Drawing**: each row is a bar from the pane's right edge leftwards, length `= rowTotal / maxRowTotal · width% · paneWidth`; `up` next to the edge, `down` beyond it; alpha 0.7 inside the value area, 0.3 outside; POC = a 2 px line across the pane at the POC row's middle price. Recomputed when the visible bar indices, the last visible bar (realtime), the bars array or `rows`/`valueArea` change; checked once per chart repaint (`updateAllViews`), so at most one recompute per frame.
- Fixture: `volume_profile_numpy` in `gen_fixtures.py` (a bars × rows overlap matrix and the same value-area walk) on fixed slices of both fixture datasets (`volumeProfiles` in the JSON; the AAPL slices include flat bars).

## Phase 10: Ichimoku Cloud (`ichimoku`, locked)

Params: `conversion` 9, `base` 26, `spanB` 52, `displacement` 26 (TradingView defaults). `mid(n)` = (highest high + lowest low)/2 of the last `n` bars, first at `i = n−1`. The calc emits UNSHIFTED values at the bar where they are computed: `tenkan = mid(conversion)`, `kijun = mid(base)`, `leadA = (tenkan + kijun)/2` (once both exist), `leadB = mid(spanB)`, `lagging = close` (every bar). Drawing shifts them by `LineDef.offset` (Pine's Ichimoku): `leadA`/`leadB` forward `displacement − 1` bars, `lagging` back `displacement − 1` bars. Colours: tenkan `#2962ff`, kijun `#b71c1c`, lagging `#43a047`, leadA `#a5d6a7`, leadB `#ef9a9a`. Fixture: `talib.MIDPRICE` (asserted equal to pandas rolling max/min in `gen_fixtures.py`).

### Ichimoku drawing

- **Offset lines** (`LineDef.offset(params)` = `k`, any indicator): the point computed at bar `i` is drawn at bar `i + k`. Ichimoku: `leadA`/`leadB` `k = displacement − 1`, `lagging` `k = 1 − displacement` (Pine `offset`). Points that land before bar 0 are dropped. Points that land past the last bar (`k > 0`) are not fed to the series (no future times on the time scale) but kept as `future` points at logical index `i + k`. The series, legend and `debug()` use the shifted points (`shiftLine` in `indicatorData.ts`); a realtime bar redoes only the tail (`shiftUpdate`): one `series.update`, or `setData` if a point vanished, and must equal a full shift.
- **Cloud** (`IndicatorDef.cloud = ['leadA', 'leadB']`, `CloudPrimitive` attached to the leadA series, `zOrder` `bottom`): filled on every bar (logical index, in data and future) where both shifted lines have a value; colour = leadA's where `A ≥ B`, else leadB's, alpha 0.25, instance colours. Between two bars where `A − B` changes sign the fill is split at the linear crossing. The future part of leadA/leadB (up to `displacement − 1` bars right of the last candle) is drawn by the primitive with the line's colour and width, starting at the line's point on the last candle. `autoscaleInfo` adds the visible future values to the price range.
